spec-104 capacity measurement

2026-09-21 · scripts/spec104_capacity_measure.py · branch spec/104-staged-process-isolation

Goal

Answer two questions for the spec-104 per-step process isolation work (SIGHTING-117 durable fix): how does peak memory scale with album size N, and what does isolation cost versus the in-process path now that per-step release() is in place? This is the real-pipeline measurement behind the REVIEW.md §5 follow-up.

Method

The representative-heavy faces pipeline (YOLO, InsightFace, MediaPipe, DINOv2, AVA, pyiqa — real models, no feature cache) runs on N = 100 / 300 / 500 images from the Germany trip set, downsampled to 768 px longest edge. Each configuration runs in a fresh spawn child; a monitor samples the peak process-tree RSS (resident memory of the pipeline parent plus any isolated step children) at ~150 ms intervals. Isolated runs use isolate_steps=True (each step in its own spawn child, 300 s per-step timeout); in-process runs are the default path. Environment: Windows 10 dev box, 32 GB RAM, CPU-only inference.

Findings

Memory scaling is flat. Peak ≈ a fixed model floor plus a small linear term: isolated ≈ 2,511 MB + 0.67 MB/image; in-process ≈ 2,341 MB + 0.38 MB/image. Model weights dominate (~93% of peak at N=100); per-image context (embeddings, face records, scores) is KB-scale. No N² term is active in this pipeline (the only N×N producer, spec-103 build_scene_distance, is gated off by default).
Capacity is not memory-bound. Extrapolating the isolated line: a 16 GB box fits ≈ 20,000 images per run; the 32 GB dev box ≈ 44,000. Runtime binds first: ~1.6 s/image on CPU means 20k images ≈ 9 h. A 4 GB per-worker budget is safe with headroom, so production concurrency is k ≈ RAM / 4 GB, capped by cores.
Isolation cost is modest: +~300 MB peak, +10% wall time at N=500 — despite each step child reloading its models. The peak overhead is mostly the pipeline parent's own baseline RSS sitting alongside the step child in the tree; the doubled slope (0.67 vs 0.38 MB/image) is the context marshaling (pickling in/out of each child) — measurable, harmless at this scale.
In-process no longer loses on peak. After the SIGHTING-117 per-step release() fixes, the default path stacks no models, so v1 isolation buys robustness (a child crash or OOM cannot kill the run; memory return is guaranteed by process exit), not a peak-RSS win on this pipeline. Both modes completed all runs.
Anomaly — small face-count divergence between modes (455 vs 454 at N=300; 794 vs 796 at N=500; identical at N=100). Filed as SIGHTING-122; the REVIEW.md §5 output-equivalence test must either root-cause this or carry an explicit tolerance.
