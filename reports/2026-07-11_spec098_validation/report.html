spec-098 validation: noise-aware quality scoring

Goal. Verify the spec-098 fix (noise-robust sharpness + wavelet noise component) against its pre-registered acceptance gates, by re-running the 2026-07-10 defect-scoring benchmarks unchanged. Baseline reports: reports/2026-07-10_defect_noise/, reports/2026-07-10_defect_blur/.

The shipped formula (evolution matters)

The first attempt — median-blur-then-Laplacian only — failed its own gates (SIDD overall pair acc 62% vs ≥95%; inflation 11× vs <2×). Two parameter sweeps (scripts/experiment_spec098_sweep{,2,3}.py) produced the shipped formula:

sharpness = max( LaplacianVar( median3(img) ) − 5·σ², 0 ),   σ = wavelet noise estimate (green channel, 1024px central crop, 33 ms @ 16 MP)

plus a noise component 1/(1+σ/2) and rebalanced weights sharpness .30 / exposure .25 / colorfulness .05 / contrast .10 / noise .30 (colorfulness cut .20→.05 — chroma noise inflates it).

A4 — face blur gate re-calibration (user-approved option 1)

The corrected formula scores 112×112 face crops at ~0.45× the old scale (rank corr 0.93 over the 340 Budapest faces), so the absolute gate blur_min=150 over-rejected 4×. Re-calibrated 150 → 73.3 (minimizes gate flips: 19/340 faces) in profile_4.json and profile_5.json; profiles 1–3/smoke have the gate off (0). Migration note

Any profile in the wild with a nonzero blur_min tuned for the old Laplacian scale should be scaled by ~0.49 (the 150→73.3 mapping). The score_iqa universal-cache key was bumped (rule_based → rule_based_v2) so stale v1 whole-image scores are never served; a unit test pins the bump.

Verdict: spec-098 ships. The pipeline no longer prefers noisy images (0/480 → 477/480 correct), blur ranking is intact (99.3%), the face gate is noise-robust with a calibrated threshold, and the Studio gains a sortable Noise column. Fix proposals for the two other red defect findings (exposure compression, rotation blindness) remain open as separate specs.
