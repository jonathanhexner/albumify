Why this happens

Screenshots are flat, sharp, high-contrast, perfectly exposed, no faces, no occlusion — so IQA/AVA love them. Quality scoring structurally rewards junk. You cannot filter screenshots by scoring them lower; they must be removed before curation. This is the empirical proof for a triage gate.

The one-line answer

Face detection + face embedding = ~1.66 s of the ~2.2 s per image (75%). Scene, people, and quality scoring together are the other 25%. This is model compute (per-image), not model load (that's a one-time cost, already amortized here). So the bottleneck is real work, and the fix is a faster execution target — not warmer caches alone.

*This run used the faces pipeline, which drops the two heaviest steps (occlusion CLIP + GeoCalib tilt). The full default pipeline would add those on top. On CPU this is far beyond interactive — the capacity work already flagged runtime, not memory, as the ceiling. The levers: GPU for the InsightFace/ONNX stack (typically 10–50×), caching per-image features, or deferring the face stack when the album ranking doesn't need per-face identity.

04 · Next steps

What this run tells us to do

1

Build the triage gate — it's now proven, not theoreticaldo first

30% of the album was junk, and junk out-scored real photos. Ship the pre-curation gate: metadata (free, caught all 8 screenshots) → RAM++ content (caught 2 posters metadata missed) → set aside for review, never silent-delete. This is a small, high-impact pipeline step and a v1 necessity for the live upload path.

2

Re-run Stage A on the cleaned set + your keepersdo first

We can't grade curation while junk dominates. With triage on, compare Albumify's picks to your keeper list on the full trip (precision/recall). The 14 real picks here look promising — now measure it honestly.

3

Decide the runtime targetbefore serving

2.2 s/img (faces-only, CPU) × a real roll = tens of minutes — not interactive. The face stack is 75%. Choose: GPU worker (biggest win), feature caching, or defer/skip face embedding for album ranking. This directly sizes the spec-106 serving decision.

4

Test the behavioral + intent layer on the full rollv1.5

The singleton signal was inconclusive on a sampled subset. Run it on the contiguous roll to see if it catches the utilitarian shots (car/CDs/ladder) that quality can't. If not, that's the case for the scoped VLM-intent judge (agentic layer).

5

Fold into the finalization planplan

Triage moves into Stage B (engine finalization) as a required pre-curation step; the runtime decision feeds Stage C (serving). The finalization roadmap already has the slots.
