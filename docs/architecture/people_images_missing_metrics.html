People & Faces: the "Selected" filter and face boxes are blank

Albumify · Streamlit + FastAPI · 2026-06-25

✓ RESOLVED — spec-086 (2026-06-25). Fixed at the data layer, not the symptom: normalized image_metric_rows / face_metric_rows tables in the central API DB + an ImageRepository SQL JOIN now feed get_person_images. The break point (stage 2) no longer drops metrics. Verified live: 54 images, 7 selected / 47 not-selected, with bboxes. See specs/086-image-repository-over-rundb/.

1 · Symptom

What you see Open a person → their photo gallery. The Selected filter shows nothing; "Sort by Score" does nothing; and the Image Detail popup draws no boxes around the faces — even though faces are exactly what the page is about.

2 · Cause in one line

Root cause The endpoint that lists a person's photos returns only 3 fields per photo (image_path, face_count, faces) — so is_selected, composite_score, and the face filter_scores (which carry the box coordinates) never reach the page.

3 · Plain analogy

A paper form with only 3 blank lines: photo name, face count, face list. Anything not on the form is thrown away before it reaches the screen. The page then asks "was this photo selected?" and "where are the faces?" — those lines were never on the form, so the answers come back blank. The filter matches nothing; the boxes have no coordinates to draw.

4 · Background (who's this for)

For an engineer new to this code. Albumify picks the best photos from an album. A pipeline scores every image, groups faces into people, and marks some images selected. The People & Faces page lets you click a person and browse their photos. All per-image numbers (scores, selection flag, face boxes) live in one DB blob — PipelineResult.image_metrics — keyed by image path.

6 · Smoking-gun proof

A real photo's image_metrics row in the DB carries the full data — is_selected and per-face bbox with pixel coords:

filter_scores[0] = {face_index:0, confidence:0.83,
                    bbox:{x_px:1719, y_px:730, w_px:511, h_px:776}}   # exists in DB
face_pose_scores = [0.86, 0.00]                                       # exists in DB

But get_person_images() returns {image_path, face_count, faces} — the exact 3 fields that do work, and not one more. The fields that vanish are precisely the ones the endpoint never copies.

9 · Senior-engineer take

This is the same class of bug as spec-084's blank Results columns: a per-image metric silently not reaching a UI surface because an intermediate hand-built dict + a narrow response_model drop it. spec-085 already built the cure — ImageMetrics, one canonical per-image shape — and migrated the Results/Explore path to it. The People path was simply never migrated. Fix = route it through the same primitive, and the bug can't recur (a parity test guards the schema).
