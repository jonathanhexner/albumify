The 4 registry patterns (one per concern)

① DB access

Typed Repository + Service over the DB. No raw SQL in UI.
face_cluster/repositories views/*Service
EXISTS · enforced

② Input / config

Params declared once in FCParams; widgets auto-render via UI_SPEC+factory.
fc_params.py ui_spec.py widget_factory.py
EXISTS · enforced

③ Display tables

Columns declared once as ColumnSpec; one renderer loops them.
views/_specs.py ColumnSpec render_run_table
EXISTS · partial use

④ Metric strips

No MetricSpec equivalent — every st.metric is hand-written.
~34 calls (v2) ~63 calls (Albumify)
MISSING · everywhere

①②③ mirror the same idea (one declaration → one renderer → zero duplication). ④ is the gap behind your face-metrics / area-% pain.
