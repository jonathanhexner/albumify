How these docs stay correct

  1. Spec lifecycle (WORKFLOW.md): Draft → In Progress → Code Review → Implemented. No skipping Code Review.
  2. Code Review gate (docs/guides/CODE_REVIEW_CHECKLIST.md): every spec runs /code-review before being marked Implemented. §7 of the checklist asks "is the architecture documentation updated?" — must be Pass before handoff.
  3. CI architecture tests (tests/architecture/): drift between code and spec breaks the build (e.g., a new PipelineContext field without a row in spec-034 fails CI).

If a doc looks wrong

Don't fix it silently. File a sighting in docs/project/SIGHTINGS.md (or fix-and-log-learning if trivial). Drift between code and doc is itself a finding that future reviewers should see.
