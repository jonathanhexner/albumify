2. Face Detection & Embedding

Uses InsightFace buffalo_l (SCRFD detector + ArcFace recognizer) to detect faces and extract 512-dimensional embeddings in a single pass.

Process per image

  1. Load image via PIL with EXIF auto-rotation
  2. Convert to RGB numpy array
  3. Run InsightFace app.get(img_rgb) — returns face objects with bbox, landmarks, embedding, pose
  4. Sort detected faces by configured ordering (detection order, reading order, area, or confidence)
  5. For each face:
    • Extract 512-dim embedding, L2-normalize
    • Extract pose (yaw, pitch, roll) from the 1k3d68 landmark model
    • Generate 112×112 aligned crop via face_align.norm_crop()
    • Create a FaceRecord with all metadata
Embedding normalization embedding_normalized = embedding / ||embedding||2
Important: Face ordering is critical for reproducibility. The same image processed with different ordering settings will produce different face_id→embedding mappings. The pipeline always uses the same ordering within a run.

3. Quality Gating

Separates faces into a core set (high quality, used for clustering) and a holdout set (lower quality, optionally attached later). This prevents blurry, profile, or tiny faces from corrupting cluster quality.

Selection process

  1. Per-image top-K filter: Group faces by source image. Keep only the top max_faces_per_image_core faces by area. This prevents one group photo from dominating the core set.
  2. Pose angle filter: Reject faces with extreme angles:
    • |yaw| > yaw_max (looking too far left/right)
    • |pitch| > pitch_max (looking too far up/down)
    • |roll| > roll_max (head tilted too far)
    If pose data is unavailable and require_pose=False (default), the face passes this filter.
  3. Blur filter: Reject faces with blur_score < blur_min.
  4. Area filter (optional): Reject faces smaller than min_face_area pixels.
Blur score (Laplacian variance) blur_score = Var(Laplacian(grayscale_crop_112x112))
Higher = sharper. Typical values: blurry < 30, sharp > 100.
ParameterDefaultEffect
yaw_max30.0Degrees. Reject extreme left/right profiles
pitch_max25.0Degrees. Reject extreme up/down gaze
roll_max25.0Degrees. Reject excessive head tilt
blur_min50.0Laplacian variance. Reject blurry faces
max_faces_per_image_core3Top-K by area per image
min_face_areaNonePixels. Optional floor on face size
require_poseFalseIf True, no-pose faces go to holdout

4. kNN Graph Construction

Builds a mutual k-nearest-neighbor graph from core face embeddings. This graph is the foundation for clustering — two faces are connected only if they are close and mutually consider each other neighbors.

Steps

  1. Distance matrix: Compute pairwise cosine distance between all core embeddings.
  2. kNN search: For each face, find the K closest other faces by sorting distances.
  3. Mutual filtering: Create an edge between face i and face j only if:
    • j is in the K nearest neighbors of i, AND
    • i is in the K nearest neighbors of j (the relationship is mutual), AND
    • distance(i, j) ≤ distance_threshold
Cosine distance D[i,j] = clamp(1.0 - dot(E[i], E[j]), 0, 2)
where E is the L2-normalized embedding matrix. D=0 means identical, D=2 means opposite.
The mutual requirement is crucial — it prevents "bridge" edges where face A considers face B close, but B has many closer neighbors and wouldn't naturally group with A. This reduces transitive closure problems where unrelated faces chain together.
ParameterDefaultEffect
K5Number of nearest neighbors. Higher = more edges = larger clusters
distance_threshold0.35Max cosine distance for edges. Lower = stricter = more clusters

5. Connected Components Clustering

The simplest and most interpretable clustering step: faces that are connected through any path of mutual-kNN edges belong to the same cluster.

Algorithm

  1. Find all connected components in the mutual kNN graph (using NetworkX).
  2. Components with ≥ min_cluster_size faces become clusters.
  3. Smaller components are marked as noise (label = -1).
  4. Compute per-cluster statistics: size, diameter (max pairwise distance), median/mean/P95 distance.
Cluster diameter diameter(C) = max { D[i,j] : i,j in C, i ≠ j }
The worst-case pairwise distance within the cluster. Used by split and merge safeguards.
ParameterDefaultEffect
min_cluster_size2Min faces to form a cluster. 1 = keep singletons

6. Exemplar Selection

Selects a small set of representative faces per cluster. Exemplars are used by the merge stage to compare clusters efficiently and by the UI to display cluster thumbnails.

D10 density metric

For each face in a cluster, compute d10 — the distance to its kth nearest neighbor within the same cluster. Faces with low d10 are in dense regions (surrounded by similar faces), making them good representatives.

Selection algorithm

  1. Compute d10 for every face in the cluster.
  2. Filter candidates: keep faces with d10 ≤ exemplars_d10_threshold.
  3. Sort candidates by d10 ascending (densest first).
  4. Greedy selection with suppression: Walk through candidates in order. Accept a candidate only if it is at least exemplar_suppression_radius away from all already-accepted exemplars. This ensures exemplars are spread across the cluster, not clumped in one region.
  5. Stop after selecting N_exemplars_max exemplars.
D10 metric d10(face_i) = sorted(distances_within_cluster[i])[k]
where k = d10_k. Skip self-distance (which is 0). Lower d10 = more central face.
ParameterDefaultEffect
d10_k3K for d10 computation
exemplars_d10_threshold0.35Max d10 to be candidate exemplar
N_exemplars_max10Max exemplars per cluster
exemplar_suppression_radius0.2Min distance between selected exemplars

7. Cluster Splitting (Optional)

A safety net for clusters that are too wide — likely containing faces from different people connected through a chain of borderline edges.

Algorithm

  1. For each cluster where diameter > split_diameter_threshold:
  2. Build a new internal mutual kNN graph using tighter parameters (split_K, split_distance_threshold).
  3. Find connected components in the internal graph.
  4. If 2+ sub-components have ≥ min_cluster_size faces: replace the original cluster with sub-clusters.
  5. Faces not in any valid sub-component become noise.
Split is disabled by default (split_enabled=False). Enable it when you suspect transitive closure is linking unrelated faces — a common symptom is clusters with large diameter (>0.6) containing visually different faces.
ParameterDefaultEffect
split_enabledFalseEnable/disable split safeguard
split_diameter_threshold0.6Trigger split if cluster diameter exceeds this
split_distance_threshold0.30Tighter edge threshold for internal graph
split_K3Fewer neighbors for internal graph

8. Conservative Merge (Optional)

The initial clustering (connected components on mutual kNN) tends to under-merge: the same person may end up in multiple clusters because their faces lack mutual kNN edges between groups (e.g., different lighting, angles, or time periods). The conservative merge stage corrects this by merging cluster pairs that pass all four evidence gates.

8a. Candidate Proposal

Before evaluating the expensive 4-gate criteria, a cheap pre-filter identifies plausible merge candidates:

  1. For each pair of clusters (i, j):
  2. Compute the minimum exemplar-to-exemplar distance: min{D[a,b] : a in exemplars(i), b in exemplars(j)}
  3. If this minimum distance ≤ merge_candidate_threshold, add (i, j) as a candidate.

merge_candidate_threshold (default 0.45) is intentionally loose — it just filters out obviously unrelated pairs to save compute. The actual decision is made by the four gates below.

8b. Adaptive Thresholds

Rather than using a single fixed threshold for all clusters, the merge stage computes per-cluster adaptive thresholds based on each cluster's internal spread:

  1. Per-cluster threshold Ti: For cluster i, compute all pairwise distances between its exemplars. Ti = P{exemplar_percentile} of these distances.
  2. Global threshold Tglobal: Take all per-cluster thresholds and compute Tglobal = P{global_percentile} across them.
  3. Merge threshold for pair (A, B):
Adaptive merge threshold Tlocal = max(TA, TB)    (use the more permissive cluster)
Tmerge = α × Tlocal + β × Tglobal

Default: α=0.70, β=0.30, exemplar_percentile=90, global_percentile=50
Both α and β are independently settable (0 to 2). They are NOT constrained to sum to 1.

Intuition: A tight cluster (small Ti) should require close exemplars to merge. A loose cluster (large Ti) naturally tolerates more distance. The global component prevents any single cluster's threshold from dominating.

8c. The Four Gates

Every candidate pair must pass all four gates to be merged. If any gate fails, the pair is rejected.

Gate A: Exemplar Agreement

The closest exemplars from the two clusters must be within the adaptive threshold.

exemplar_dist = min { D[a,b] : a ∈ exemplars(CA), b ∈ exemplars(CB) }
PASS if: exemplar_dist ≤ Tmerge

Tuning: To loosen, raise merge_threshold_alpha, merge_exemplar_percentile, or merge_global_percentile.

Gate B: Support Count

There must be enough cross-cluster face pairs with distance below the threshold — not just one lucky pair of exemplars.

support = count { (a,b) : a ∈ CA, b ∈ CB, D[a,b] ≤ Tmerge }
required = max(merge_support_frac × min(|CA|, |CB|),   merge_support_min)
PASS if: support ≥ required

Tuning: To loosen, lower merge_support_frac or merge_support_min. Setting merge_support_min=1 allows merges with just one close cross-cluster pair.

Gate C: Margin Check

Prevents ambiguous merges where cluster B isn't clearly the best match for A — some other cluster C might be just as close.

For each exemplar e in CA:
  d_B = min distance from e to any face in CB
  d_C = min distance from e to any face in Cother
PASS if: d_B + merge_margin ≤ d_C   for all other clusters C

Tuning: Set merge_margin=0 to disable this gate entirely.

Gate D: Post-Merge Diameter

The hypothetical merged cluster must not be too much wider than the original clusters.

post_diameter = max { D[i,j] : i,j ∈ CA ∪ CB }
max_allowed = merge_diameter_expansion_factor × max(diameter(CA), diameter(CB))
PASS if: post_diameter ≤ max_allowed

Tuning: Raise merge_diameter_expansion_factor (default 1.5). A value of 2.0 allows the merged cluster to be twice as wide as the widest original.

8d. Iterative Merging

Merging runs in a loop:

  1. Propose all candidate pairs.
  2. Evaluate all four gates for each candidate.
  3. Among valid merges, pick the one with the smallest exemplar distance (most confident merge).
  4. Execute that merge: combine the two clusters, recompute exemplars and stats.
  5. If adaptive thresholds are enabled, recompute all thresholds (since cluster compositions changed).
  6. Repeat from step 1 until no valid merges remain or max iterations reached.
One merge per iteration: Only the single best merge is performed per loop. This is conservative — each merge changes the cluster landscape, and we recompute thresholds before the next decision. This prevents cascading errors where an early bad merge invalidates subsequent decisions.

All decisions (merged and rejected) are logged to merge_log.json for post-hoc analysis in the Merge Analysis tab.

9. Holdout Attachment (Optional)

After clustering is complete, holdout faces (rejected by quality gating) can be assigned to clusters. This is useful for people who appear mostly in low-quality photos.

Algorithm per holdout face

  1. Compute distance from the holdout face to each cluster's exemplars.
  2. Identify the best cluster (minimum distance) and the second-best.
  3. Check three conditions:
    • Distance: dbest ≤ attach_distance_threshold
    • Margin: dbest + margin ≤ dsecond (the face clearly belongs to one cluster, not ambiguously between two)
    • Voting: Among the Kattach nearest core faces, at least vote_min belong to the best cluster
  4. If all three pass: attach to best cluster. Otherwise: mark as noise.
Attachment decision attach(h) to best_cluster   if:
  d_best ≤ attach_distance_threshold
  AND   d_best + margin ≤ d_second
  AND   count{k-nearest core faces in best_cluster} ≥ vote_min
ParameterDefaultEffect
attach_enabledFalseEnable holdout attachment
attach_distance_threshold0.35Max distance to nearest cluster
K_attach5Neighbors to check for voting
vote_min3Minimum votes from K_attach neighbors
margin0.1Margin to second-best cluster
