3 · Hardcoded columns — audit

The Repository is the only file with raw SQL. Column names appear in 4 statements:

L131-132  SELECT cluster_id, size, diameter, avg_intra_dist FROM clusters WHERE iteration = ? ORDER BY cluster_id
L136-137  SELECT cluster_id, COUNT(*) FROM cluster_assignments WHERE iteration = ? AND is_exemplar = 1 GROUP BY cluster_id
L169      SELECT face_id, cluster_id, is_exemplar FROM cluster_assignments WHERE iteration = ?
L324      SELECT MAX(iteration) FROM clusters

Acceptable Per-run schema lives in face_cluster/db/schema.py; RunStore's PRAGMA user_version check fails loud on drift. The 7 column literals here are 1-source — concentrated in one file, in 4 statements. There is no parallel "column list" constant duplicating them (compare with the legacy _COLUMNS registry that spec-046 retired).

Note If the per-run schema ever moves to SQLAlchemy/Alembic (out of scope; would change the Repository from B0b to B0a), these statements should be replaced with select(Cluster.cluster_id, ...). Tracked implicitly under spec-046's "applies to every future Repository" scope.

No hardcoded columns elsewhere Service module (cluster_analysis.py): 0 column-string literals. All components: 0 column-string literals. Tab orchestrator: 0 column-string literals.

4 · Duplications + code smells

SMELL-1 Duplicated distance-matrix helper

Where. face_cluster/views/cluster_analysis.py:_distance_matrix (line 242, ~13 LOC) reimplements the same cosine-distance math already in face_cluster/views/_base.py:_pairwise_distances + _embeddings_matrix (used by ClusterView, ClusterDebugView, run_overview, cluster_debug_view).

Why it happened. The legacy _get_distance_matrix at app/face_clustering/tabs/cluster_analysis_tab.py:77 takes a PipelineResult and returns the matrix; I ported it verbatim instead of composing the existing _base.py helpers.

Fix. 1-line refactor: mat = _embeddings_matrix(faces, list(range(len(faces)))); return _pairwise_distances(mat) if mat is not None else None. ~13 LOC removed. Filed for follow-up — not blocking; the duplicate is correct, just redundant.

SMELL-2 Tech-debt seam: _build_pipeline_result_proxy

Where. cluster_analysis.py:_build_pipeline_result_proxy assembles a fake legacy PipelineResult so the unchanged ClusterView.compute / ClusterDebugView.compute classmethods accept Repository-shaped input.

Why it exists. Already documented as spec D5: refactoring those classmethods to take typed inputs is deferred. The proxy is the single seam where new typed code meets legacy untyped code.

Status. Accepted Spec.§"Out of scope" already calls this out. The 8-LOC noise-filter inside the proxy is load-bearing (Phase 4 bug fix: ClusterView.compute crashed when the noise bucket's empty-exemplar list reached np.stack).

SMELL-3 Components total 240 LOC vs 200 target (+20%)

Where. force_merge.py 62 LOC (target 50) and cluster_debug.py 49 LOC (target 40) account for most of the overage.

Why. Both manage non-trivial inline state (force-merge preview persistence; heatmap visibility). Splitting either would create render-helpers that are called from exactly one place — premature abstraction.

Status. Accept Each component still ≤ 100 LOC and has one render function; no single component crosses the per-file 100-LOC threshold the spec suggests as the real bar.

SMELL-4 Hard-coded 512-dim leaks from legacy snapshot writer

Where. face_cluster/manual_merge_snapshot.py:170 uses EMB_DIM = 512 as a constant. The synthetic test fixture had to bump from 16-dim → 512-dim to match. If InsightFace ever changes its dim, two files need a coordinated update.

Fix. Read the dim from faces[0].embedding_normalized.shape[0] instead of a constant. One-line change in the legacy writer; filed as a sighting against manual_merge_snapshot, out of spec-045 scope.

5 · What stayed clean

  • No reverse imports. Tab imports Components; Components import Service types; Service imports Repository; nothing climbs back up.
  • No cross-component imports. The 6 components don't import each other — they're stateless render functions composed by the tab.
  • No cfg.get('field', '?') literals. Arch test #2 enforces this in perpetuity.
  • No bare -1 for noise. Every cluster-id check routes through NOISE_LABEL / is_noise() (commit 9824d84).
  • No silent dict returns. Every Service method has a typed return annotation; arch test #3 enforces. ForceMergePreview replaces the legacy untyped force-merge dict (12 keys) one-for-one.
  • Two-way drift guard. Arch test #5 locks ForceMergePreview field set against ForceMergeResult — adding a gate to the preview without piping it to the writer fails CI.
