SIGHTING-080 postmortem

The History tab's "Load Run" button rejected every v2 run as missing artifacts. The error contradicted itself in plain sight. 2026-05-29.

Headline. The History tab was checking for legacy v4 CSV files (faces.csv, clusters.csv) that v2 runs do not produce. spec-040 Phase 4 replaced those CSVs with a single face_clustering.db per run; the History tab's artifact list never got updated. Every v2 run failed the gate even though load_pipeline_result could open it. Third instance this week of a v2 code path failing because it was ported assuming a pre-spec-040 layout — pattern flagged below.

1. What the user saw

Run is incomplete (status: complete).
Cannot load — required artifacts (faces.csv, clusters.csv, embeddings.npy)
are missing or status is not 'complete'.
The contradiction in plain sight. The error string says both things at once:
  • "status: complete" ✓ — the run finished cleanly. pipeline_run.json says so. action_log status column says so.
  • "required artifacts … are missing" ✓ — yes, the legacy CSVs are missing. They were never written.
Both were technically true, but the artifact list being checked was wrong for the era. v2 runs write face_clustering.db (sqlite), not faces.csv + clusters.csv.

2. Why it happened — the two-version-era mismatch

spec-040 Phase 4 (schema v5, landed weeks ago) collapsed the legacy CSV trio into a single sqlite DB per run. The on-disk shape of a completed v2 run is:

~/.sim_bench/runs/<uuid>/
  face_clustering.db         <-- v5: all rows live here (faces, clusters, assignments, merges, run_metadata, ...)
  embeddings.npy              <-- bulk embeddings (still .npy — too big for sqlite)
  embedding_face_ids.npy
  pipeline_run.json           <-- run-level manifest + schema_version
  crops/                       <-- face thumbnails

No faces.csv. No clusters.csv. Three valid layouts exist on disk across the repo's history:

EraLayoutProducers
v5 (current)face_clustering.db at top levelfc_app_v2, current Albumify
v4 transitional (spec-030)_v4/face_clustering.dbbrief migration window
Legacy CSV (pre-spec-030)faces.csv + clusters.csv + embeddings.npyold runs still on disk

face_cluster.loader.load_pipeline_result already handled all three (tries v4 transitional first, then v5, then falls back to CSV). But the History tab's pre-flight artifact check was a separate code path that only knew about the CSV layout:

# face_cluster/views/history.py:246-250 (broken)
_REQUIRED_ARTIFACTS = (
    "faces.csv",
    "clusters.csv",
    "embeddings.npy",
)
...
has_required = all((out_dir / a).exists() for a in _REQUIRED_ARTIFACTS)

For every v2 run, has_required was False. load_button.py read that flag and rendered the disabled-button-plus-warning state. The user could see the run in the table, see status: complete, see the run dir on disk — and still couldn't load it.

3. The fix

Replace the hardcoded list with a function that matches load_pipeline_result's actual behavior. 
def _run_dir_has_loadable_artifacts(out_dir: Path) -> bool:
    if not out_dir.exists():
        return False
    if (out_dir / "face_clustering.db").is_file():          # v5 (current)
        return True
    if (out_dir / "_v4" / "face_clustering.db").is_file():   # v4 transitional
        return True
    return all((out_dir / a).is_file() for a in            # legacy CSV trio
               ("faces.csv", "clusters.csv", "embeddings.npy"))

Plus error-message rewrites in two places so the text matches reality:

LocationWasNow
history.py:load_run "missing required artifacts: ['faces.csv', ...]" "no loadable artifacts ... expected one of: face_clustering.db (v5), _v4/face_clustering.db (transitional), or faces.csv+clusters.csv+embeddings.npy (legacy CSV)"
load_button.py warning Hardcoded the v4 CSV trio in the user-facing text Differentiates "status not complete" from "no loadable artifacts"; lists all three valid layouts

4. How no unit test caught this — the load-bearing question

Test layerWhat it coveredWhy it missed
test_history_service_synthetic.py (~30 cases) HistoryService query / mutation surface, including test_load_run_raises_when_artifacts_missing The artifact-check test used legacy CSV fixtures that matched the broken constant by accident. It asserted "missing CSVs → error" — which was true. It never asked "what if the v5 DB is present?" because the v5 layout didn't exist in any test fixture.
test_history_service_real.py (3 cases, opt-in) Smoke against the user's real action_log DB Read-only smoke (list / get / count). Never called load_run, so the artifact gate was never exercised against a real v2 run.
test_v2_app_smoke.py AppTest (3 cases) Page-level: cold start, empty run dir, no-op-merge run Only tests the Cluster Analysis tab path (the SIGHTING-078 / -079 surface). History tab path wasn't exercised — would have needed a seeded action_log row, which the AppTest didn't construct.
Architecture tests Layering (no DB in tabs, typed returns, etc.) Structural — by design, doesn't catch behavior bugs like "constant is the wrong list".
The structural lesson. Hardcoded "what's a valid X" constants drift when the underlying definition changes elsewhere. _REQUIRED_ARTIFACTS in history.py was the source-of-truth for one layer; load_pipeline_result in loader.py was the source-of-truth for another. They diverged when spec-040 landed without anyone wiring them together. The drift-guard pattern (a test that asserts "every layout load_pipeline_result accepts is also accepted by the History artifact check") would have caught this — and is exactly what the new test_history_service_v5_artifacts.py shipped as the regression net.

5. The pattern — three sightings in a week

SIGHTING-080 is the third v2 code path this week that failed because it was ported assuming a pre-spec-040 layout:

SightingWhat was ported assuming the old shape
SIGHTING-078RunStore._resolve_iteration("final") assumed merge_decisions and clusters always had rows at the same iteration. Broke when the merger considered pairs but merged none (common in v5-era runs).
SIGHTING-079AsyncHandle[T] ported the legacy _AsyncState shape but not its time.sleep + st.rerun() polling loop. Streamlit doesn't poll background threads — handle never reached the UI.
SIGHTING-080_REQUIRED_ARTIFACTS kept the legacy CSV trio after spec-040 collapsed everything into face_clustering.db. History tab rejected every v2 run.

Worth filing a focused mini-spec: audit every v2 read path against the v5 reality. Candidates: any constant ending in _ARTIFACTS, _REQUIRED, _COLUMNS; any function that hardcodes file names like faces.csv or clusters.csv; any place that calls RunStore.<method>("final") instead of an explicit int.

6. Tests added (regression net)

1. Unit-level (the contract): tests/face_clustering/views/test_history_service_v5_artifacts.py — 7 cases pinning every layout load_pipeline_result accepts plus partial / pathological cases. This is the drift guard.
2. End-to-end (per user request): tests/face_clustering/test_v2_app_smoke.py now has 2 new AppTest cases. One seeds a v2 run into the action_log and verifies the History tab renders without exception + without the legacy-artifact warning. One drives HistoryService.load_run against the seeded run and asserts it returns a typed LoadedRun without raising.
3. Updated stale test: test_load_run_raises_when_artifacts_missing — wording updated for the new "no loadable artifacts" error. Still pins the "empty dir → error" case, which is the contract that didn't change.
