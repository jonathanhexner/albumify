6 · How to drive this with agents (sequential)

Agents available (from system prompt):
  • Plan — read-only architect. Use FIRST to refine each per-spec plan before implementation.
  • general-purpose — multi-step implementer with write access.
  • spec-implementer — your custom agent (commit 686b635). Refuses to start without a spec dir; refuses to finish without REVIEW.md. The natural choice for each tab.

Recommended sequential flow per spec:

For spec in [063, 064, 065, 066]:
    1. Spawn Plan agent to refine the implementation plan (read-only, ~5 min)
       Prompt: "Read specs/<spec>/{spec,tasks}.md + tests/face_clustering/e2e_budapest/README.md.
                Produce a step-by-step plan for implementing this spec, including
                the e2e scenario file and README row update. Don't write code."
    2. Review the plan; tweak if needed.
    3. Spawn spec-implementer (or general-purpose) to execute.
       Prompt: "Implement specs/<spec> per its tasks.md. Follow the E2E contract
                section verbatim — create the named test file with the listed
                concrete assertions, update e2e_budapest/README.md, update
                conftest.py if the spec lists new constants. End by running
                `pytest -m budapest tests/face_clustering/e2e_budapest/`;
                ALL scenarios must be green before you flip the spec to Implemented."
    4. Review the diff. Commit + push.
    5. Move to the next spec.

Why sequential, not parallel: all 4 specs touch app/face_clustering_v2/main.py (tab registration), tests/face_clustering/e2e_budapest/README.md (matrix table), tests/face_clustering/e2e_budapest/conftest.py (constants), and CHANGES_LOG.md. Sequential = zero merge conflict cost. Parallel-in-worktrees = ~30 min merge reconciliation per pair.
