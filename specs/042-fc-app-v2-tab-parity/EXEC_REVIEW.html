What we set out to do

The legacy app/face_clustering/ app (3,160 LOC across 11 tabs) accumulated drift over a year of feature work:

  • 35+ hand-rolled cfg.get('field', '?') literals duplicating config field names across tabs.
  • Tabs averaging ~290 LOC, several mixing 5+ responsibilities (UI + SQL + JSON parsing + business logic).
  • Zero unit tests across the entire tab layer.
  • Files like history_tab.py (365 LOC), cluster_analysis_tab.py (383 LOC), label_tab.py (604 LOC).

The rebuild target (spec-042) is an FC App v2 with the same user-facing workflow but:

  • A layered architecture: Tab → Service → Repository → DB, each layer testable in isolation.
  • Typed boundaries everywhere (dataclasses, Pydantic, Pandera).
  • Tests at three layers per tab: synthetic unit / real-fixture smoke / Playwright UI.
  • Zero cfg.get() literals; config flows through a single typed container (FCParams, shipped in spec-041).

Concrete benefits delivered

BenefitBeforeAfter
Cost of adding an action_log column 9 hand-maintained places to edit. Forgetting one = silent runtime bug. 2 places (_COLUMNS + RunRow). Arch tests fail loudly if either is forgotten.
History tab test coverage 0 unit tests across the legacy tab. 75 tests: 33 Repository synthetic + 3 real-fixture + 31 Service synthetic + 4 real-fixture + 4 arch.
DB access from UI code Tabs ran SQL directly. Refactors broke silently. Arch test forbids DB imports in tabs/ & components/. Enforced at PR time.
Test isolation Shadowed-import trap: from X import Y captured at import time, defeated monkeypatches (caused real test escape in spec-042 H1). Each Repository owns its DB path via typed Config — no global state, no shadowed imports.
Error contract Mixed ValueError / RuntimeError / silent returns. Typed ServiceError hierarchy (NotFoundError, ValidationError) with user-safe user_message. Future FastAPI maps these to HTTP codes with no per-endpoint logic.

Patterns codified (binding for all future work)

Lives in docs/architecture/architecture_standards.md. Each is enforced by an arch test, not just prose.

StandardPlain EnglishWhy it matters
A6 Per-tab migration discipline Each migrated tab ships with DB + Backend + Frontend tests. Both apps run at every commit. No "big bang" cutover. Reversible at any step.
B0 Repository pattern Persistence is a class with typed Config + composable typed Criteria. Not module-level free functions. No global state, no shadowed-import traps, adding a config option is non-breaking.
B0.1 Column Registry For schema-owning Repositories: one _COLUMNS table drives everything. Adding a column = 2 edits. Eliminates an entire class of "forgot to update X" bugs.
B2 Typed error hierarchy Services raise ServiceError subclasses with a user_message. Never plain ValueError. UI catches once and displays. Future FastAPI maps to HTTP codes mechanically.
B3 Service vocabulary Five-verb taxonomy: list_* / get_* / create_* / update_* / delete_*. Predictable surface; no naming-by-author bikeshedding.

Risks & learnings

Risks tracked

RiskSeverityMitigation in place
Two Repository flavors confuse contributors — without explicit B0a/B0b in standards, someone might apply Column Registry where it doesn't fit (or skip it where it does). MED spec-045 Phase 8 (T074) adds the prose. Until then, the design comparison HTML is the reference.
Async pattern is awkward (background thread + 400ms time.sleep polling + st.rerun()). Wrapped behind AsyncHandle[T], but the underlying mechanism still re-runs the whole script every 400ms during compute. LOW Streamlit limitation, not architectural. AsyncHandle isolates the wart so a future swap (e.g., @st.cache_data) only touches one file.
Velocity assumption for remaining 7 tabs (~30–50h) is based on the pattern being template-applicable. Recluster is the genuine unknown (new runner mode). MED Cluster Analysis (spec-045) is the load test of the assumption. After it ships we'll have a real per-tab data point.
Architecture HTMLs lag code (the F-1/F-2 findings) — classes.html and db_global.html drifted before being caught at code review. Fixed for spec-043/044, but the drift mechanism still exists. LOW Documentation-update mandate codified in CODE_REVIEW_CHECKLIST §7. /code-review command flags doc drift as a finding.

Learnings logged

  • Shadowed-import trap (spec-042 H1): from X import Y captures the binding at import time; monkeypatches that re-bind X.Y are silently defeated. Fix: always use module-attribute access (X.Y()) when the function is an injection point. Codified as Standard B1.
  • Per-row 9-place duplication smell (spec-044 motivation): if you have 9 hand-maintained constants describing the same thing, declare it once and derive the rest. Codified as Standard A2 (already existed) and B0.1 (new).
  • Streamlit hot-reload doesn't re-import (2026-05-27): script changes reload but module objects (cached classes) don't. Restart the server after adding fields/methods to classes used by long-lived imports.

Bottom line

We've completed the foundational work for the v2 rebuild and shipped 1 of 8 tabs. The pattern is documented, tested, and binding. The next tab is fully designed.

The remaining work is well-bounded — most tabs are template applications of the established Repository → Service → Tab shape. The biggest unknowns are concentrated in 1 of 7 tabs (Recluster, P1, new runner mode). At the current cadence we are on track to retire the legacy 3,160-LOC tab layer in ~2 weeks of focused work.
