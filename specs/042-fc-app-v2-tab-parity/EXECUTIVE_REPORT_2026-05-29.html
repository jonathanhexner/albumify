2. Why does it feel like everything is broken?

Honest answer: because the v2 app is half-built on top of a system mid-refactor, and the tests we wrote don't actually run the app. Three concrete reasons stacked:
  1. Two on-disk layouts coexist. Old runs wrote faces.csv + clusters.csv + an in-DB embeddings table. spec-040 (months ago) replaced both with one face_clustering.db + embeddings.npy. Every v2 component was written against some understanding of which layout to expect; the four sightings this week were components written against the wrong one.
  2. Tests verified contracts, not user actions. The synthetic fixtures used to write empty strings into the crop_path DB column, which made every test pass while masking that FaceRecord wouldn't accept the field. The unit tests were genuinely green — they just weren't testing the thing the user clicks.
  3. Specs 056-058 are mid-flight. Files are moving (face_cluster/run_store.py → sim_bench/run_db/store.py; face_cluster/repositories/cluster_analysis_repo.py → sim_bench/db/face_clustering/cluster_analysis_repo.py). When a file moves with a behavior change baked in (the new crop_path kwarg in store.py), the contract on the receiving end (FaceRecord) gets out of sync. That's how HEAD ended up with a latent bug nobody noticed until I poked it.
