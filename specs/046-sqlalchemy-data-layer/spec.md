# Feature Specification: SQLAlchemy + Alembic Data Layer

**Created**: 2026-05-28
**Status**: Implemented
**Predecessors**: spec-043 (Repository pattern), spec-044 (Column Registry — retired by this spec)
**Successors**: spec-047 (full-system E2E gate)

---

## Problem

`RunHistoryRepository` hand-rolls schema definition (`_COLUMNS` / `ColumnDef`) and migrations (`_create_table_sql` / `_MIGRATION_COLUMNS`) — work that SQLAlchemy + Alembic do as standard. Any new developer must learn our bespoke pattern before they can safely add a column or write an isolated test.

This spec swaps the bespoke implementation for the textbook one. **Goal: code that is recognisable, safe to modify, and boring.**

---

## What we build

| Layer | Module | Purpose |
|---|---|---|
| ORM base | `face_cluster/repositories/_orm_base.py` | `Base(DeclarativeBase)` + Alembic naming convention |
| Engine | `face_cluster/repositories/_engine.py` | SQLite engine factory with WAL + foreign-key pragmas |
| Session | `face_cluster/repositories/_session.py` | `sessionmaker` + `session_scope()` context manager |
| Base repo | `face_cluster/repositories/_base_repository.py` | Shared `find` / `count` / error-translation logic |
| ORM model | `face_cluster/repositories/models/action_log.py` | `ActionLog` — replaces `_COLUMNS` |
| Repository | `face_cluster/repositories/run_history_repo.py` | `RunHistoryRepository(BaseRepository)` — SQLAlchemy-backed |
| Migrations | `alembic/` + `alembic.ini` | Versioned schema history; baseline = current production schema |
| Test fixtures | `tests/face_clustering/repositories/conftest.py` | `transactional_session`, `golden_run_history_db_path` |
| Golden fixture | `tests/face_clustering/fixtures/golden_run_history.db` | Real data from `D:\sim-bench\test_data\face_clustering` |

Future Repositories (spec-045, etc.) inherit `BaseRepository` and write one ORM model + one Repository file.

## What we don't build

- Per-run `face_clustering.db` (RunStore) — spec-045 problem
- Global `sim_bench.db` (caches, embeddings) — separate concern
- Async SQLAlchemy — Streamlit is sync
- Full pipeline-to-UI E2E test — spec-047

---

## Locked decisions

1. **SQLAlchemy 2.0 typed API only** — `Mapped[T]`, `mapped_column()`, `select()`. No legacy `Query`.
2. **Caller-injected sessions** — `RunHistoryRepository(session: Session)`. Factory `make_run_history_repo(db_path)` wraps engine + session creation for callers that don't want to manage transactions.
3. **`v2` suffix is temporary** — only during Phase 5 (parallel coexistence for equivalence test). Renamed back at Phase 6.
4. **Golden fixture is real data, checked into git** — built once via legacy pipeline against real test images; rebuild script provided.
5. **Legacy shims become thin delegators** — `run_history.py`, `run_history_db.py` route to new Repository; deletion still scheduled 2026-06-08.

## Out-of-scope risks (track but don't fix here)

- Production users have existing `face_history.db` files. First launch after deploy must `alembic stamp head` (no data migration, just version marker). Phase 3 test proves this is idempotent.
- 10 legacy consumers in `app/face_clustering/` and `scripts/` still import the old free functions. They're covered by Phase 7 (shims keep working). Final deletion is the 2026-06-08 burn-in task.
