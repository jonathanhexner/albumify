3. Findings

3.1 Code smells

SMELL-1 [RESOLVED in spec-048 Phase 1] Subprocess shell-out to alembic.exe from production code. run_history_repo.py::_ensure_schema calls subprocess.run([.venv/Scripts/alembic.exe, "upgrade", "head"]) when a fresh DB needs the schema. This is slow (~250 ms per fresh DB), Windows-only (hardcoded .exe), and brittle (any change to the venv layout breaks it).

Fix: use alembic.command.upgrade(cfg, "head") from the Python API. Removes the subprocess, removes the venv-path coupling, ~3 ms per call. → Replaced by face_cluster/repositories/_schema.py::ensure_schema. Drift guard: tests/architecture/test_no_subprocess_alembic_in_repos.py.
SMELL-2 duplication [RESOLVED in spec-048 Phase 1] Hardcoded .venv/Scripts/alembic.exe appears in 3 places. run_history_repo.py::_ensure_schema, tests/face_clustering/repositories/test_alembic_baseline.py, tests/architecture/test_orm_models_in_sync_with_alembic.py, plus tests/face_clustering/repositories/conftest.py. All construct the same path the same way. Fix SMELL-1 and the test usages become a single helper or the Alembic Python API directly. → All 4 sites ported to alembic.command Python API. Grep guard in tests/architecture/test_no_subprocess_alembic_in_repos.py.
SMELL-3 duplication [RESOLVED in spec-048 Phase 4] _to_run_row is a 24-line manual column-to-attribute mapping. Every column on ActionLog appears again in _to_run_row. Adding a column requires editing the ORM model AND _to_run_row AND RunRow (three places), defeating the "2-file edit" claim in §B0.2. The deleted spec-044 drift guard test_runrow_fields_match_columns_registry was preventing exactly this drift.

Fix: add a small architecture test that asserts RunRow fields ⊇ ActionLog column names. Or, better, generate RunRow from ActionLog via a small helper. → Replaced by RunRow.from_orm(model) classmethod (column-driven, 5 LOC). Drift guard: tests/architecture/test_runrow_matches_action_log.py. Byte-equivalence verified across 24 golden rows.
SMELL-4 [RESOLVED in spec-048 Phase 3] Hardcoded hot-fields tuple in run_history_repo.py. _HOT_FIELDS = ("run_id", "source_dir", ... 16 names). This is leaked from the legacy spec-044 design (columns writable through payload). It duplicates field names that the ORM model already knows. Today there's no drift guard.

Fix: either move the "is hot" attribute onto the ORM model via Column.info={"hot": True} and derive the tuple, or add a small test that asserts every name in _HOT_FIELDS exists on ActionLog. → Each hot column carries info={"updated_on_complete": True} on its mapped_column; ActionLog.hot_field_names() reads it back. Equivalence verified in tests/face_clustering/repositories/test_hot_fields.py.
SMELL-5 [RESOLVED in spec-048 Phase 2] (Engine cache removed; engine + sessionmaker now created per-instance in __init__. Drift guard: tests/architecture/test_no_module_level_caches_in_repos.py. Construction perf bound: test_repo_construction_perf.py.)

Module-level mutable _engine_cache dict. Process-wide cache of engines keyed by db_path. Works, but SQLAlchemy already has a connection pool per engine; the extra layer mostly avoids the cost of re-running _ensure_schema. Once SMELL-1 is fixed (cheap schema check), the cache is dispensable.
SMELL-6 _check_writable repeated at the top of 4 mutation methods. start_action, complete_action, fail_action, update_comment each begin with self._check_writable(). Could be a single decorator @_mutates for clarity. Low priority — 4 lines.
SMELL-7 BaseRepository static methods are unused by RunHistoryRepository. _translate_not_found / _translate_integrity are written for subclasses to inherit, but RunHistoryRepository raises NotFoundError directly without going through them. Dead code until the next Repository (spec-045) actually uses the helpers.
SMELL-8 [RESOLVED in spec-048 Phase 5] (rebuild_golden.py rewritten to use RunHistoryRepository. AST-based drift guard: tests/architecture/test_rebuild_golden_not_locked_to_legacy.py. Survives 2026-06-08 legacy-shim deletion.)

rebuild_golden.py is locked to legacy modules slated for deletion (2026-06-08). The script imports face_cluster.run_history_db free functions to seed the fixture. Once those modules are deleted in the burn-in window, the script breaks and the fixture can't be regenerated.

Fix: migrate the rebuild script to use the new RunHistoryRepository before 2026-06-08. The fixture itself is committed and stable; only regeneration breaks.

3.2 Missing contracts

CONTRACT-1 No drift guard between ActionLog ORM model and RunRow dataclass. The deleted spec-044 test (test_runrow_fields_match_columns_registry) covered this. We deleted it because _COLUMNS is gone — but RunRow still exists and still needs to mirror the ORM model. Currently no test catches "added a column to ActionLog, forgot to add it to RunRow + _to_run_row".

Risk: medium. Manifests as AttributeError at runtime when a method reads the new field via RunRow.
CONTRACT-2 RunHistoryRepoConfig kept for backwards compat but no longer extensible without breaking changes. Two fields: db_path, read_only. The legacy auto_migrate / log_queries / connection_timeout_s fields are gone (no equivalent in the new design). Tests passing these would silently fail with TypeError.

Fix: if any test or caller passed those fields, this would already have surfaced — confirm via grep. Otherwise: add a deprecation note in the Config docstring referencing spec-046.
CONTRACT-3 No __repr__ on ActionLog. Debug output shows <ActionLog 0x...>. A two-line __repr__ returning id, action_type, status would make logs and assertion failures readable.
CONTRACT-4 No type annotation on _engine_cache module-level value usage. Declared as dict[Path, tuple[Engine, sessionmaker[Session]]] but the function returning from it lacks explicit assertion that the cached tuple is well-formed. Low-priority — runtime type errors would surface immediately on the first read.

Net column-list count went from 9 unguarded (legacy) → 3 unguarded + 1 guarded (now). Progress, but not the "single source of truth" the spec advertised.

3.4 Things done well

Equivalence test as the swap-safety mechanism. 24/24 parametrised cases (reads + mutations) against real data proved byte-identical output before the swap. This is the right pattern for any data-layer migration.
Naming convention on Base.metadata. Deterministic constraint names mean alembic --autogenerate output is stable across machines. Easy to miss; we got it right.
alembic check as the permanent drift guard. Single test replaces four hand-rolled ones; the framework guarantees the invariant by construction.
Real-data fixture committed to git. 24 rows, ~50 KB, deterministic, regenerable. Beats synthetic fixtures for equivalence testing.
Shared fixtures live under tests/face_clustering/repositories/conftest.py. transactional_session + fresh_db_engine are the primitives spec-045 and every future Repository test will reuse without writing new ones.
