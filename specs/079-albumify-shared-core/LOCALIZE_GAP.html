What this changes in the plan

Re-scope. "Route Albumify's clustering onto the unified steps" does not fix the divergence — the two clustering paths already agree. The real work is unifying the producer chain so both apps feed clustering the same faces.
  • Layer A (config gates) — still real: 3 gates, 8→10. Fixed by the typed FCParams contract.
  • Layer B (was "code path") → actually the PRODUCER CHAIN — different face set (core 133 vs 186), 10→20. Fixed by running the same detect/filter/align/embed sub-chain in both apps.
  • Deleting the bridge / consolidating clustering steps stays worthwhile as cleanup (DRY, one path), but it is no longer the behavioral fix.
