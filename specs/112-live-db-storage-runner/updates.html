Decisions made while building

  • Results bundle instead of RunExporter. The exporter is face-centric (its images table is derived from faces and has no capture time, GPS or album status), needs the face-clustering app's in-memory ClusterResult objects, and keys by absolute path. A purpose-built bundle (sim_bench/album/results_bundle.py) reads the context directly; each photo row carries the pipeline's own decisions, so photos removed before scoring keep their reason (SIGHTING-128 data, without choosing the reason code: they are in_album = false, status = null).
  • ObjectStore deferred to Phase B (TA1.1 → TB1.1): in Phase A the local job directory is the storage, and every runner copies the job's files there.
  • Album contract: Person.label added (owner-given name; "" by default). Additive.
  • Control DB uses create_all (Alembic manages only sim_bench.db).
  • Viewer is not read-only: promote / remove / rename buttons write user_edits (AC5 asked for the API; the page uses it).

Blocked

  • SIGHTING-131 (cleared): the dev box's commit charge sat at its limit (126.6 / 127.9 GB), so every local model load failed (bad allocation, torch access violation in DINOv2). It cleared on its own the same evening without a reboot; tests/pipeline then passed (183) including the two tests that had crashed. Intermittent, cause unknown.
  • AC1 needs one Modal run of Slovakia26 with the bundle (the 2026-10-09 run predates it).
