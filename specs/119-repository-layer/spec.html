spec-119 — One repository layer: every database read and write goes through a repository

Status: Proposal (not approved; number provisional) · Created: 2026-11-14 · Roadmap: Stage C, after spec-117 merges · Continues: spec-086 (slice 1) · Resolves: spec-117 review M3

Colour = type of change: NEW CHANGED REMOVED. Progress = ● done · ◐ partly done · ○ planned. In the class diagram: ✚ new member · ✎ changed · ✖ removed · unmarked = unchanged.

1. Objective

Every database read and write goes through a repository (one small class per kind of data, the only code that writes queries). Services, routers, the watchdog and the GPU worker call repositories; serving/ stops importing from api/ (review M3). Results are read from the normalized metric tables instead of the JSON blobs; API responses do not change.

  • Rough size: W1–W2 about a day; W3–W4 the biggest (results payloads must match exactly); W5–W6 about a day.
  • Open question for the owner: drop the JSON blob columns after W4, or keep them for a release as a backup?
