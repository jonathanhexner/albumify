2026-10-09 — Storage-reference curate built: job store, album.json, and an album that is actually reproducible

The worker no longer takes image bytes. A job is a directory and the worker is handed its id.

stage_job(job_id, images) -> /jobs/<id>/input/*     (CPU, light image)
curate_job(job_id)        -> /jobs/<id>/album.json  (GPU) | curate_job_cpu (free tier)
fetch_album(job_id)       -> {album, run, displays}
  • New modules, all testable off Modal (this is the point — the worker body used to only be observable by paying for a container): sim_bench/serving/job_store.py (layout + job_id/filename validation, since both become paths), sim_bench/serving/curate_job.py (JobCurator.calc: read inputs → scratch copy → plan → normalize() → write album/displays/run record), sim_bench/serving/pipeline_runner.py (SpecBuilder: configs/pipeline.yaml → steps + per-step device placement, lifted verbatim out of modal_app._curate, which is now thin).
  • The run uses a scratch copy of input/ because straighten_images writes derivatives beside its inputs: without the copy, a second run of the same job would see N + derivatives. That one decision is what makes AC4 meaningful rather than accidental.
  • Found and fixed SIGHTING-126 — the album was not reproducible. Two consecutive runs over the same staged images returned the same four picks with the same composite scores, but with the scene ids swapped and the picks in a different order: extract_scene_embedding's dict order varies between runs, HDBSCAN numbers clusters by row order, and select_best iterates that dict. Fixed in album/normalizer.py (not in the clusterer — cluster ids are inherently arbitrary; the album is where a stable contract is owed): scenes renumbered by their earliest photo, picks ordered by EXIF capture time (id fallback), beat/beaten_by sorted. Scene 0 is now the trip's first scene.
  • AC5 cause fixed in code: _prepare_caches() sets HF_HUB_CACHE, TORCH_HOME (torch.hub: DINOv2/GeoCalib/pyiqa) and INSIGHTFACE_HOME, the last honored by a 4-line change in InsightFaceFaceAnalyzer._load_app; the job functions commit models_vol. buffalo_l was landing in ~/.insightface — container scratch — so it was re-downloaded every cold start.
  • Blocked locally, not by this work: the full 38-step pipeline cannot run on the dev box at all — RamTagger(device="cpu") segfaults (SIGHTING-127, filed). The local proof therefore uses minimal_pipeline; the default-pipeline comparison must be the Modal CPU run.
  • Not done: no remote run of the job path (owner's call on spend). AC3/AC4/AC5 need --job-id ... --twice on Modal, twice, to also show the second run skipping model downloads.
