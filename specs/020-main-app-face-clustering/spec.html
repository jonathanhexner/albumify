Spec 020 — Unified Face Clustering: Connected Apps

Date: 2026-04-30  |  Status: DRAFT  |  Revision: 2 (connected-apps approach)

1 Problem & Goal

The main album app and the standalone face clustering app use different clustering algorithms. Bug fixes and improvements (SIGHTING-030, spec-019 OR gate, exemplar reselection) only land in face_cluster/. The main app gets none of these.

Goal: One algorithm, two entry points. The main app uses the same face_cluster/ algorithm classes. After clustering, results are exported in the standalone app's format so the user can open them in the face clustering app for deep analysis, recluster, merge tuning, etc.

Key insight

The two apps are connected by data, not code. The main app exports face clustering artifacts in the same file format the standalone app reads. This means:

  • No shared orchestration layer needed
  • The standalone app's full power (recluster, merge analysis, parameter tuning) is available for any album
  • If the user reclusters in the standalone app, results can be re-imported into the main app
  • Each app evolves independently — the file format is the contract

3 Pipeline Change: Add Method, Don't Replace Step

Rather than creating a new pipeline step, we add face_cluster_knn as a new method in the existing cluster_people step. All existing methods (HDBSCAN, agglomerative, etc.) remain available.

Current methods in cluster_people:

hdbscan
hdbscan_pca
hybrid_hdbscan_knn
mutual_knn
agglomerative
face_cluster_knn
NEW — delegates to face_cluster/
Why add a method, not a new step?
  • No pipeline YAML changes needed — just change method: value
  • No all_steps.py registration
  • Same context output contract — people_clusters is written identically
  • User can switch back to old method instantly if needed
  • The identity_refinement step is kept — it handles noise attachment, user overrides, exemplar export. The new method writes people_clusters and identity_refinement handles the rest

4 Data Export: The Bridge Between Apps

After the face_cluster_knn method runs, it exports artifacts to results/<album>/face_clustering/ in the standalone app's format:

FileContentRequired by standalone app?
faces.csvFace metadata + cluster_id + quality verdictsYes (mandatory)
embeddings.npyn_faces x 512 float32 L2-normalizedYes (for recluster)
embedding_face_ids.npyface_id per embedding rowYes (for recluster)
pipeline_run.jsonConfig, timing, summaryYes (mandatory)
clusters.csvCluster summary (size, exemplars, diameter)For full view
merge_log.jsonMerge decisions (if merge enabled)For merge analysis
crop_manifest.jsonface_id -> crop path mappingFor crop display

This is the same format the standalone app already writes and reads. No new format to design — we reuse face_cluster/export.py functions.

5 User Flow

  1. Main app: User selects album, picks face_cluster_knn method, runs pipeline
  2. Main app: Pipeline clusters faces, exports artifacts, shows results in People tab
  3. Main app: UI shows "Analyze in Face Clustering App" link (deep-link with ?load_run=path)
  4. Standalone app: User clicks link → standalone app opens with that run loaded
  5. Standalone app: User can recluster, tune merge params, analyze merge decisions, train ML model
  6. Main app: (optional) User re-imports updated clusters from standalone app recluster

8 Risks

R1: Blur score source — QualityGater needs blur_score. Main pipeline may not store it per-face. Fix: compute from aligned crop in bridge, or skip blur gate if crops unavailable.
R2: Pose format — InsightFace returns (pitch, yaw, roll); face_cluster expects (yaw, pitch, roll). Fix: reorder in bridge function (same logic as embedding.py).
R3: Export path — must not collide with standalone app runs or previous pipeline runs. Fix: use results/<album>/face_clustering_<timestamp>/.

10 Acceptance Criteria

  1. Pipeline runs with method: face_cluster_knn — clustering correct (purity + completeness)
  2. All existing methods still work — no regression
  3. identity_refinement step runs after and produces refined_people_clusters
  4. Artifacts exported to results/<album>/face_clustering/ in standalone format
  5. Standalone app loads exported artifacts via load_pipeline_result() without errors
  6. Standalone app can recluster from exported artifacts
  7. Main app UI shows deep-link to standalone app after pipeline run
  8. At least one test exercises holdout path (quality gating rejects faces)
