T5: How Do We Show the "Open in Face Clustering App" Link?

The Problem

The main app runs on a client-server architecture:

  Streamlit Frontend          FastAPI Backend              Disk
  (browser UI)                (Python server)
  ─────────────               ──────────────              ────────
       │                           │
       │  "Run pipeline"           │
       ├──────────────────────────>│
       │                           │
       │                           ├─── runs pipeline steps ──>  writes results
       │                           │    (cluster_people runs     to DB + files
       │                           │     face_cluster_knn)
       │                           │         │
       │                           │         ├─── exports artifacts to:
       │                           │         │    results/album/face_clustering_XXX/
       │                           │         │
       │                           │    context._fc_export_dir = "results/album/..."
       │                           │         │
       │                           │    ╳ context is DISCARDED after pipeline finishes
       │                           │         │
       │  "Pipeline complete!"     │         │
       │<──────────────────────────│         │
       │                           │
       │  HOW does the frontend    │
       │  know WHERE the export    │
       │  directory is?            │
       │                           │

The gap: The export path (results/album/face_clustering_20260430/) is created inside the pipeline step, stored on an in-memory context object, and then thrown away when the pipeline finishes. The Streamlit frontend never sees it.

The standalone Face Clustering App already supports loading a run via URL: http://localhost:8502/?load_run=results/album/face_clustering_20260430 — we just need a way to get that path to the frontend.

Three Options

Option A Store path in database
  Pipeline step                   Database                    Frontend
  ─────────────                   ────────                    ────────
       │                              │
       ├── exports to disk            │
       │   results/album/fc_XXX/      │
       │                              │
       ├── saves path to DB ─────────>│  PipelineResult.fc_export_dir
       │   (new column)               │  = "results/album/fc_XXX"
       │                              │
       │                              │           │
       │                              │<──────────┤  Frontend queries
       │                              │           │  API for results
       │                              │           │
       │                              │──────────>│  Response includes
       │                              │           │  fc_export_dir
       │                              │           │
       │                              │           ├── renders link:
       │                              │           │   "Open in FC App →"
       │                              │           │   href=?load_run=...

+ Clean, reliable — path stored permanently

+ Works even if user navigates away and comes back

+ Survives app restarts

- Requires DB schema change (ALTER TABLE, new column)

- Requires API endpoint change to return the field

- More files to modify (model, service, API, frontend)

Option B — Recommended Frontend scans disk for exports
  Pipeline step                                       Frontend
  ─────────────                                       ────────
       │
       ├── exports to disk
       │   results/Austria_24/face_clustering_20260430/
       │   (deterministic path: results/{album}/face_clustering_*)
       │
       │                                                  │
       │                        Pipeline completes        │
       │                                                  │
       │                                                  ├── knows the album name
       │                                                  │   (it started the pipeline)
       │                                                  │
       │                                                  ├── scans disk:
       │                                                  │   glob("results/{album}/face_clustering_*")
       │                                                  │   → finds the directory
       │                                                  │
       │                                                  ├── renders link:
       │                                                  │   "Open in FC App →"
       │                                                  │   href=?load_run=results/...

+ Zero backend changes — no DB, no API, no model changes

+ Frontend-only: just add a glob + link in results page

+ Works immediately with existing exports

+ Finds ALL past exports, not just the latest one

- Relies on naming convention (results/{album}/face_clustering_*)

- If naming changes, link breaks (but easy to fix)

Option C Write a marker file that backend returns
  Pipeline step                   Result dir                  Frontend
  ─────────────                   ──────────                  ────────
       │                              │
       ├── exports to disk            │
       │   results/album/fc_XXX/      │
       │                              │
       ├── writes marker file ───────>│  results/{job_dir}/
       │                              │    fc_export_link.json
       │                              │    {"path": "results/album/fc_XXX"}
       │                              │
       │                              │           │
       │                              │<──────────┤  Frontend reads
       │                              │           │  job result dir
       │                              │           │
       │                              │──────────>│  Finds marker file
       │                              │           │  → renders link

+ No DB change needed

+ Explicit — path is recorded, not inferred

- Needs to know where the job result dir is

- Main app results are in DB, not always on disk

- More complex than Option B

Comparison

Criteria A: DB column B: Scan disk C: Marker file
Backend changes Model + API + service None Pipeline step only
Frontend changes Results page Results page Results page
DB migration Yes (ALTER TABLE) No No
Reliability High High (naming is deterministic) Medium
Implementation effort ~5 files ~1 file (results page) ~2 files
Works for past exports Only new runs Yes — finds any export on disk Only new runs

Recommendation: Option B

Option B is simplest and most pragmatic. The export directory follows a deterministic pattern (results/{album}/face_clustering_*). The frontend already knows the album name (it started the pipeline). One glob call finds the export directory. One link rendered.

If we later need more robustness (e.g., multiple exports per album, specific run tracking), we can upgrade to Option A. But for now B gets us the link with minimal code change.

# In results page, after pipeline completes:
import glob
album_name = st.session_state.get("selected_album_name", "")
fc_dirs = sorted(glob.glob(f"results/{album_name}/face_clustering_*"), reverse=True)
if fc_dirs:
    fc_path = fc_dirs[0]  # latest export
    fc_url = f"http://localhost:8502/?load_run={fc_path}"
    st.info(f"[Open in Face Clustering App]({fc_url}) — analyze merges, recluster, train ML")
