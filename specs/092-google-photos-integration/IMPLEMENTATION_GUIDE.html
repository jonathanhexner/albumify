Google Photos Picker — Implementation Guide

How sim-bench connects to a user's Google Photos to import selected photos, the software architecture behind it, and every module involved. Built; unit-tested; awaiting only your OAuth credentials to go live.

spec-092 Picker API (post-2025) 11 unit tests green package gphotos/

0 Overview

Since March 2025, the only live-API way to read a user's Google Photos library is the Picker API: the user selects photos inside Google's own UI, and our app receives just those items. We download the bytes into a local cache directory that the existing pipeline ingests unchanged.

# One sentence of data flow user clicks "Import" ─▶ OAuth ─▶ Picker session ─▶ user picks in browser ─▶ download =d bytes ─▶ local cache/ ─▶ existing discover_images pipeline
What's done
  • OAuth (installed-app loopback) + token cache
  • Full Picker REST client (session → poll → list → download)
  • Idempotent download cache
  • 2 standalone scripts + 11 unit tests
What you must do
  • Create a Google Cloud OAuth client (§2)
  • Drop client_secret.json at repo root
  • Run the two scripts to verify (§3)

2 Google Cloud setup YOU DO THIS

One-time, ~10 minutes, at console.cloud.google.com. This is the only part the code can't do for you.

  1. Create / select a projectTop bar → project dropdown → New Project (e.g. "sim-bench-photos").
  2. Enable the Photos Picker APIAPIs & Services → Library → search "Photos Picker API" → Enable. (Do not enable the legacy Library API — not needed for import.)
  3. Configure the OAuth consent screenAPIs & Services → OAuth consent screen → User type External → fill app name + your email. Leave publishing status as Testing.
  4. Add the scopeOn the consent screen's Scopes step, add .../auth/photospicker.mediaitems.readonly (or skip here — the code requests it at runtime).
  5. Add yourself as a Test userConsent screen → Test users → Add users → your Google email. Required while in Testing mode (≤100 users, no security review).
  6. Create the OAuth client IDCredentials → Create credentials → OAuth client ID → Application type Desktop app → Create.
  7. Download & place the secretDownload JSON → save as D:\sim-bench\client_secret.json. Done.
Why "Desktop app" + "Testing" Desktop-app clients use the loopback redirect (127.0.0.1) our auth flow relies on. Testing mode lets the restricted-free Picker scope work immediately for up to 100 named users with no Google review — perfect for a personal/internal tool. Going public later would add OAuth verification (a separate decision, see the decision report).

4 Software architecture

A single self-contained package gphotos/ sits at the edge of the system. It depends on Google's libraries and our own types — nothing depends back on the pipeline. The output is a folder of image files, the same contract the app already uses for local folders.

5 Module reference

gphotos/types.py no I/O · no deps

Framework-agnostic dataclasses that mirror the verified Picker REST schema. Each parses raw JSON via a from_api() classmethod, so the rest of the package never touches dict keys.

TypeFields / purpose
PollingConfigpoll_interval_s, timeout_s — server-recommended poll cadence.
PickerSessionid, picker_uri, media_items_set, polling, expire_time. from_api(data) → PickerSession
PickedItemid, filename, base_url, mime_type, media_type, create_time + is_video. from_api(data) → PickedItem
DownloadedItemitem, local_path — a picked item after its bytes land on disk.
_parse_durationHelper: protobuf Duration string ("3.5s") → float seconds, with default fallback.

gphotos/auth.py OAuth

Installed-app (loopback) OAuth with on-disk token caching and silent refresh.

class GooglePhotosAuth:
    def __init__(self, client_secret_path, scopes=(PICKER_SCOPE,), token_path=DEFAULT_TOKEN_PATH)
    def get_credentials(self, open_browser=True) -> Credentials   # load → refresh → or run consent
    def clear(self)                                          # delete cached token
  • PICKER_SCOPE = .../auth/photospicker.mediaitems.readonly
  • DEFAULT_TOKEN_PATH = ~/.sim_bench/gphotos_token.json (created with 0600 where supported)
  • Logic: valid cached token → return; expired with refresh token → refresh + save; else run InstalledAppFlow.run_local_server(port=0).
  • Keyring storage is a P7 hardening follow-up; the file store already satisfies "persist once, refresh silently" (FR-008).

gphotos/picker.py REST client

Plain REST over https://photospicker.googleapis.com/v1 (no official Python client lib). Auth via AuthorizedSession, which injects + refreshes the bearer token — required even for byte downloads.

class PickerClient:
    def __init__(self, credentials=None, session=None)        # inject a fake session in tests
    def create_session(self) -> PickerSession                # POST /sessions
    def get_session(self, session_id) -> PickerSession      # GET  /sessions/{id}
    def poll_until_ready(self, session, on_wait=None, sleep=time.sleep) -> PickerSession
    def list_media_items(self, session_id, page_size=100) -> list[PickedItem]   # GET /mediaItems (paginated)
    def download_item(self, item, dest) -> Path             # GET {baseUrl}=d → write bytes
    def delete_session(self, session_id)                    # DELETE /sessions/{id} (best-effort)
EndpointMethodNotes
/v1/sessionsPOSTReturns pickerUri + pollingConfig.
/v1/sessions/{id}GETPoll until mediaItemsSet == true.
/v1/mediaItems?sessionId=GETPage size ≤100; follows nextPageToken.
{baseUrl}=dGETFull bytes, EXIF kept except GPS. Needs the bearer header.

Timeout/interval are locked from the initial session — re-fetched poll responses may omit pollingConfig, so reading them each loop would silently reset the budget (a bug caught in testing).

gphotos/cache.py materialize

Writes picked bytes into a directory the pipeline consumes as-is. Idempotent via a small manifest, so re-runs are cheap and resumable.

class DownloadCache:
    def __init__(self, root)
    def materialize(self, client, items: list[PickedItem]) -> list[DownloadedItem]
  • Skips items already on disk (id present in .gphotos_manifest.json + file exists).
  • Sanitizes filenames and disambiguates collisions (same.jpg → same_1.jpg).
  • Returns DownloadedItems carrying the original picked metadata + local path.

9 Constraints & gotchas

ConstraintImplication
Per-session, user-pickedNo library browse/search/auto-sync. Each import = one picker session the user completes.
GPS stripped on =dImported photos carry timestamp/camera EXIF but no location. Accepted risk; geo/trip detection degrades. GPS recovery (Takeout) is the separate P1 track.
Bearer header on baseUrlDownloads need the OAuth token, not just the API calls. Handled by AuthorizedSession.
Session expiryPicked items are reachable only until expireTime; download promptly.
Quotas~75k media-byte downloads/project/day; back off on 429 (P7 hardening).
Secretsclient_secret.json and the token file are credentials — git-ignored, never logged.

11 Troubleshooting

SymptomCause → fix
FileNotFoundError: client secretNo client_secret.json → complete §2; pass --client-secret PATH if elsewhere.
Browser: "app isn't verified"Expected in Testing mode → click Advanced → continue. Ensure your email is a Test user.
403 on downloadMissing bearer on baseUrl → use PickerClient (AuthorizedSession), not a bare requests.get.
access_denied at consentYour account isn't in the Test users list → add it (§2 step 5).
Poll never finishesUser didn't click Done in the picker, or session expired → re-run; the loop raises TimeoutError after the budget.
Re-consent every runToken not persisting → check write access to ~/.sim_bench/; pass --token PATH.
