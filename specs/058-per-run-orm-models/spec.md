# spec-058 — Per-run face_clustering.db ORM models (no Alembic)

**Created**: 2026-05-29
**Status**: Draft
**Predecessors**: spec-057 (RunExporter split — required so the new writers can pivot to ORM models one at a time)
**Successors**: spec-059 (Cluster Analysis Repository + RunStore on SQLAlchemy)
**Trigger**: spec-045 chose raw sqlite3 over SQLAlchemy because the per-run schema's source of truth is `face_cluster/db/schema.py` (DDL strings), not an ORM model. Closing the gap unlocks typed column access for every per-run-DB reader and writer.

---

## Problem

Three audiences want type-safe column access to the per-run `face_clustering.db`:

- `RunStore` (617 LOC) — every read method writes `row["cluster_id"]`-style untyped lookups.
- spec-057's new writer modules — each one will write raw `INSERT INTO faces (...)` strings against the same column names.
- spec-059's `ClusterAnalysisRepository` — has 4 SQL statements with 7 column-string literals.

All three reference the same schema in `db/schema.py`. Adding a column today means updating 4+ files: DDL constant, the writer that emits it, the reader that consumes it, and the test fixtures. Drift between these is the same class of bug spec-046 fixed for `action_log`.

**Why this is *not* spec-046 redux.** Alembic doesn't fit per-run DBs:

- Per-run DBs are created fresh by `RunExporter` per run; they're never *migrated*. When `SCHEMA_VERSION` bumps, old runs become unreadable — that's the documented contract, not a bug.
- Alembic's value (autogenerated migration scripts under version control) has nothing to migrate.

So we want SQLAlchemy's typed-column benefit *without* Alembic's migration machinery.

## What we build

```
face_cluster/db/
  schema.py                 # KEEP — still the DDL source for legacy callers + RunExporter bootstrap
  models/
    __init__.py
    _base.py                # DeclarativeBase + naming convention (per-run-DB flavor; no Alembic)
    face.py                 # Mapped[int] face_id, Mapped[str] image_path, ... (mirrors FACES_DDL)
    cluster.py              # Mapped[int] cluster_id, ...
    cluster_assignment.py
    merge_decision.py
    filter_decision.py
    image.py
    scene_cluster.py
    scene_cluster_assignment.py
    run_metadata.py
```

Each ORM model declares the same columns the corresponding DDL string in `schema.py` declares. The **single source of truth flips**: the ORM model becomes canonical; `schema.py`'s DDL constants are derived from `Base.metadata.create_all()` and only kept around for backward compat during the burn-in.

**Drift guard.** A new architecture test runs `CREATE TABLE` from both sides (ORM `create_all()` and `schema.py` DDL) into two temp DBs and `sqldiff`s them. Any divergence fails the test. Plays the same role `alembic check` plays for spec-046's `action_log` — without Alembic.

## What we don't build

- **No Alembic.** Per-run DBs aren't migrated; adding Alembic just to delete `versions/` would be ceremony.
- **No callers migrated yet.** RunExporter writers still use raw SQL strings in this spec; spec-059 flips them to ORM. Keeping the migration in a separate spec makes the diff readable.
- **No `RunStore` refactor.** Same reason — spec-059 owns that.
- **No new tables.** The ORM models mirror today's schema exactly. Schema evolution stays governed by `SCHEMA_VERSION` bumps.

## Locked decisions

1. **ORM model is the source of truth.** When `SCHEMA_VERSION` bumps, the ORM model changes first; the DDL constants in `schema.py` regenerate from `Base.metadata`.
2. **No Alembic.** A drift-guard test replaces it.
3. **Per-run DB connections are short-lived.** No SQLAlchemy `Session` pooling, no shared engine. Each call opens its own connection (same pattern RunStore uses today).
4. **Naming convention shared with spec-046's `Base`?** **No** — separate `Base` because the per-run DB has its own lifecycle and constraint-name namespace. Two `DeclarativeBase` subclasses, one per database.

## Risks

- **DDL textual drift.** SQLAlchemy `create_all()` may emit slightly different DDL (column order, default formatting) than today's hand-rolled strings. AC2 catches this — the test compares post-CREATE schema, not the raw DDL text, so cosmetic differences are fine but semantic ones fail.
- **Index handling.** `INDEXES_DDL` lives outside any per-table file. Decide: keep as a module-level Index list, or attach via `__table_args__` per model. Recommendation: `__table_args__`.
