Face Clustering Pipeline Map

Albumify path (mode=main_app_export) — the one in use. FC App standalone path noted only where it diverges.

One-line summary. Face clustering is inline inside cluster_people, not a separate pipeline step. The bridge face_cluster_bridge.py drops five FaceRecord fields and force-disables the quality gates that would have caught the resulting defects. Every gap reported in SIGHTING-059 is downstream of that one boundary.

Per-image observability — the join that doesn't exist yet

To answer "show everything we know about image X", today you'd need:

  1. Look up image-level scores → no table holds these
  2. Find all faces on this image → SELECT * FROM faces WHERE image_path=? (works, many NULL columns)
  3. Get per-face scoring → JOIN face_scores (mostly NULL on Albumify)
  4. Get cluster assignment per face → JOIN cluster_assignments (works)
  5. Get per-face filter decisions → JOIN filter_decisions WHERE item_type='face' (empty on Albumify)
  6. Get image-level filter decisions → WHERE item_type='image' AND item_id=image_path (empty on Albumify)

Three of six joins return empty or all-NULL on the current Albumify run. The cleanup plan's P-C closes those gaps; P-D wraps the whole join in RunStore.image_detail(image_path).
