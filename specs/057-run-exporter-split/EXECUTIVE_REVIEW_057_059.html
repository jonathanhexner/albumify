7. Recommendation — sequencing

Recommended order: 058 → 057 → 059.

StepWhyEffortRisk
1. spec-058 (per-run ORM models) Additive. Zero behavior change. Establishes the type-safe column source that 057 and 059 can both target. Drift guard gives you a green light before any real churn. 4-6 hlow
2a. spec-057 (modified) — writers emit ORM, not raw SQL Same split, same byte-equivalence gate, but writers go straight to session.add(Face(...)). Eliminates the "touch every writer twice" cost. The byte-equivalence test still catches drift. 6-8 hmed
2b. spec-057 (as-specified) — writers split with raw SQL Lower-risk variant if you want the split landed independent of any ORM concern. 059 then flips them. 6-8 h (+ ~2 h re-touch in 059)low
3. spec-059 — RunStore + CARepo to ORM The payoff. ORM and split writers exist; this collapses 851 LOC of read-path raw SQL onto Mapped types. 5-6 hmed (perf, hydration)

Total: ~15-20 h. Worth doing in the order above as three separate PRs, each independently revertable. Do not bundle into one PR — the byte-equivalence and perf gates lose meaning when stacked.

8. Open questions for the spec authors

  1. 057: How are non-deterministic outputs (timestamps in pipeline_run.json, file mtimes in crops/) handled in the golden-hash test? Either pin a clock fixture or exclude those bytes from the hash.
  2. 058: Spec says "ORM model becomes canonical; schema.py DDL derived." How is SCHEMA_DDL serialized at import time without circular imports between schema.py and models/? Recommend: schema.py imports from models, not the other way.
  3. 058: Recommend confirming there's no production code relying on the exact text of FACES_DDL (e.g. doc generation, schema-diff tooling). A grep would close this.
  4. 059: Streamlit polling cadence — does the Cluster Analysis tab poll faster than the per-call engine-creation cost? If yes, the suggestion "cache the engine on (run_dir, st.session_id)" should be in scope, not deferred.
  5. 059 vs. spec-051: Confirm that tests/face_clustering/run_store/ fixtures don't open a connection ahead of the new sessionmaker. Connection-precedence bugs are easy to ship.

9.4 Cross-spec invariants (DO NOT violate)

  1. Single canonical import path per class. Old paths under face_cluster.{run_exporter, run_store, db.schema, repositories.cluster_analysis_repo} do not exist after spec-056. Enforced by arch test.
  2. Two distinct Base classes. face_cluster/repositories/_orm_base.py (sim_bench.db, with Alembic) vs sim_bench/run_db/_base.py (per-run DB, no Alembic). Never merge.
  3. Two distinct sessionmakers. face_cluster/repositories/_session.py (sim_bench.db) vs sim_bench/run_db/_session.py (per-run DB). Never cross-import.
  4. Public surface frozen. Every RunExporter, RunStore, ClusterAnalysisRepository method keeps signature and return shape. Test suites prove this.
  5. Writers are functions, not classes. If a writer grows state, refactor the data (Inputs sub-dataclass), not the writer.
  6. One transaction per export(). The facade opens the session, BEGINs once, calls every DB writer in fixed order, COMMITs once. Writer modules never open their own session.
  7. RunStore _load_and_validate() stays on raw sqlite3. Runs PRAGMA user_version before any ORM machinery. ORM access only after validation passes.
