Verdict

One regression, two locations. spec-041 audit-fix commit c9ec26c tightened requires on the two steps above to document real reads — correct intent, but it collided with BaseStep.validate()'s "empty == error" rule for a key whose empty state is legal. spec-040 status table currently marks Phase 6 ✅; that row is stale and Phase 7 / merge-to-main is unenforceable until this is fixed.

Three fixes — pick one

OptionChangeBlast radiusRisk
A · Narrow Drop holdout_indices from the two steps' requires. Keep depends_on=["quality_gate_faces"] so the producer-ran guarantee remains. 2 lines, 2 steps. Lowest. Loses one diagnostic ("we read this key") for those two steps.
B · Broad Change BaseStep.validate() so "required" means "not None"; empty collections become valid. One file, every step inherits. Medium. Need to audit any step that currently relies on empty-as-error.
