Image Analysis Studio — Architecture

Consolidated spec-094 (absorbs spec-095 Geo-Vision). Backend = spec-093. Status: Design · updated 2026-07-03

One app, two pages. Point at a folder, pick per-image methods across two families (image quality geo & caption), run them, and browse the results as a sortable, clickable-thumbnail table — with a map for the geo family. Every score persists in universal_cache; every run is snapshotted to a sub-folder so it can be re-opened later without recomputing. spec-095's map + accuracy fold in here as the geo tab; the standalone geo app is retired.

1 · Layered architecture

5
App / UI — app/image_studio/{main,view}.py (Streamlit). Navbar: Configure Run (pick folder + methods → Run) and Browse Run (open a saved run). Browse has a top-level Quality | Geo toggle — the two families get different views, not just different columns: Quality = sortable ranking table (worst→best); Geo = map (EXIF vs GeoCLIP) + accuracy + caption table. No mixed "All" table. Pure rendering; zero model logic. restructure: navbar + Browse + Quality|Geo toggle
4
RunStore NEW — persists a run (its methods, image list, column results) as a snapshot. FolderRunStore writes <folder>/.studio_runs/<run_id>/ now; a future DbRunStore swaps to the Albumify universal DB behind the same interface.
3
Engine — app/image_studio/engine.py. A METHODS registry (one entry per method), run_methods() (groups methods by backing step, merges configs, runs each step once), and AnalysisColumn — the uniform per-image output (kind = numeric | label_conf | text | coord). This one abstraction makes "flat vs category tabs" a pure view concern.
2
Pipeline steps (sim_bench/pipeline/steps/) — each method is backed by a real, universal_cache-persisted step: ScoreQualityStep (spec-093), score_iqa, score_ava, and the geo steps (extract_geo_metadata, infer_geo_clip, infer_geo_coords, caption_images). Same steps run inside Albumify's pipeline.
1
Models — image_quality_models (PyIQAModel = 6 pyiqa metrics + AVA + rule-based IQA, via create_model) and geo_cluster helpers (StreetCLIP, GeoCLIP, BLIP, EXIF).

3 · Data flow

CONFIGURE RUN folder + limit ──► engine.discover_images ──► [paths] paths + selected methods └─► engine.run_methods(paths, selected, cache_handler) • group methods by backing step (maniqa+niqe+brisque → one score_quality run) • each step: read universal_cache ─ hit? use it : compute + write • map each step's context output ──► {path: {method: AnalysisColumn}} └─► RunStore.save(run_id, folder, methods, columns) ──► <folder>/.studio_runs/<run_id>/ BROWSE RUN RunStore.list(folder) ──► [run manifests] pick run ──► RunStore.load(run_id) ──► columns ├─ [Quality] ──► ranking table (sortable worst→best, score bars) └─ [Geo] ──► map (EXIF vs GeoCLIP) + accuracy + caption table (no recompute; top-level toggle, no mixed "All" view)

4 · Run storage — sub-folders now, DB later

FolderRunStore (build now)

D:/Budapest2025_Google/ .studio_runs/ 2026-07-03_143000_maniqa-niqe/ run.json ← folder, methods, image list, timestamps, spec version results.csv ← image × method score + rank
  • Portable, standalone, zero schema/migration.
  • Scores still live in universal_cache; the sub-folder is the run manifest + snapshot.
  • Deleting .studio_runs/ loses run history, not scores.

DbRunStore (future — Albumify)

  • Same RunStore interface: save / list / load.
  • Backed by the Albumify universal DB (a runs table) once the studio integrates.
  • Swap is one wiring line; no UI or engine change (strangler-fig).

Decision: start with folders. Don't couple the standalone studio to the DB prematurely — Albumify already owns run history; the studio adopts it at integration time.

6 · Consolidation: spec-095 folds in

spec-095 (Geo-Vision Studio) was a second, geo-only app on the same engine. It is merged into this studio and retired as a standalone. Its unique parts move into the geo & caption tab of Browse Run:
  • Map — EXIF (green) vs GeoCLIP#1 (orange) pins (geo_view.map_points).
  • Accuracy — GeoCLIP top-1 within N km of EXIF GPS (geo_view.geoclip_accuracy, haversine).
  • Confidence bars — already in the studio's table renderer.
app/geo_vision/geo_view.py (pure, unit-tested) is kept and imported by the studio; the standalone geo_vision/main.py is dropped.
