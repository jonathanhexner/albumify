Status: In Progress — build started 2026-10-04. Design of record: architecture.html (four planes, warm-up∥upload lifecycle, resolution tiers, show-everything, secrets, job state machine, observability/durability). Phase detail: plan.html. Host decided: Modal (GPU worker scaffolded in spec-109).

Design notes (decisions, from architecture.html)

  • Two shapes, one reuses the engine. The image pipeline (38 steps in curate) reuses PipelineExecutor as-is on Modal (device=cuda). The job orchestration is a NEW small event-driven state machine (control plane) — async/cross-service/long-lived; the existing synchronous executor does not fit it.
  • GPU is mandatory, not optional. The full-pipeline CPU baseline is 9 s/img → non-interactive (spec-109 T0.1). The live product runs on the Modal L4 worker. (This corrects the earlier "CPU ships v1, GPU is a later optimization" note — that was wrong.)
  • Resolution tiers: browser downscales to 768px for ALL photos (analysis + review); ~1600px display for keepers; original download-only. Don't upload full-res for analysis.
  • Warm-up ∥ upload: fire the GPU warm-up when upload STARTS so the cold start hides under the upload.
  • Storage-reference, not inline bytes: browser uploads 768px directly to storage via a short-lived presigned URL; the API passes job_id; curate pulls from storage (idempotent → free resume).
  • Show everything: curation is a proposal, not a verdict. album.json carries EVERY photo + its drop reason; all are browsable + one-click promotable. Extends spec-107 set_aside.
  • Secrets: Modal token + object-store creds on trusted hosts only (Vercel env / Modal Secret); NEVER in git / image / browser. Browser gets only scoped, expiring presigned URLs.
  • Observability/durability: every stage + step writes to the DB (jobs, job_events, pipeline_steps); the job is config too (job_pipeline.yaml-style); resume = idempotent re-run from the persisted stage. No heavyweight workflow engine.
  • Design tokens: design_drafts/albumify_landing.html → the app theme (both light/dark).
