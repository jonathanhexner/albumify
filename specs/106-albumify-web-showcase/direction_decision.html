DIRECTION A

The Showcase

"Don't sell the tool — prove it. Let people walk through three real trips the engine already curated, and show we out-reasoned a frontier VLM."

Mock: album gallery — picks ringed & flagged, dimmed frames are what got culled; a "why picked" strip + the vs-VLM hook.

🛠 Engineering

  • Next.js static export on Vercel — no backend, no model hosting
  • Precomputed JSON + 768px images (Phase 0 confirmed 100% ready)
  • Zero OOM / cost / reliability surface — literally cannot break live
Risk: minimal · Ship: days

📈 Sales

  • Positioning: credibility & rigor — "we benchmarked vs GPT/Claude"
  • Audience: recruiters, technical evaluators, early design partners
  • Differentiator most demos lack: an honest head-to-head result
Converts belief, not signups
Best when the goal is proof and credibility fast, with zero chance of an embarrassing live failure.

🛠 Engineering

  • Must host the full ML stack (torch · InsightFace · YOLO · CLIP · DINOv2)
  • Real risk: memory (SIGHTING-117 OOM), cost, cold starts, queueing
  • Needs a GPU/CPU worker, job queue, storage, reliability hardening
Risk: high · Ship: weeks

📈 Sales

  • Positioning: a launched service — the real "0→100" story
  • Audience: end users / a market you can charge
  • Caveat: a slow or failed first run destroys trust instantly
Highest ceiling, highest stakes
Best when we're committing to launch a product and can fund the reliability work to keep it un-embarrassing.

The Hybrid Funnel

Mock: the showcase gallery with a capped "try-it" module — real enough to convince, bounded so it can't blow up.

🛠 Engineering

  • Static showcase + one small bounded function (cap N, light pipeline variant)
  • Capping input side-steps the OOM/cost/latency risks of B
  • One contained live path to harden — not the whole product
Risk: medium · Ship: 1–2 weeks

📈 Sales

  • Positioning: proof that converts — credibility + a live "aha"
  • Audience: both — evaluators AND prospects, in one funnel
  • Showcase builds trust; the try-it captures intent
Best belief-to-signup path
Best when we want a real live moment without betting the launch on hosting the full pipeline.

Recommendation (for discussion — not the decision)

Sequence, don't choose: A now, C next, B only on a real launch commitment.

STEP 1 · THIS WEEK

Ship A

Bulletproof, data-ready, un-embarrassing. Earns credibility immediately and costs almost nothing.

STEP 2 · IF TRACTION

Add C's try-it

One bounded live path bolted onto the showcase. Turns belief into signups without the full hosting risk.

STEP 3 · IF FUNDED

Grow into B

Only when we commit to a launch and the reliability budget the live pipeline demands.

Each step stands alone and de-risks the next — so no step is wasted if we stop. The decision needed today: do we start at A (recommended), commit straight to B, or scope C as the first build?
