What happened: "core_indices is empty" at build_face_knn_graph

2026-05-24 · spec-041 follow-up · post-mortem of the second pre-fix crash you saw

TL;DR: Same root cause as the inhomogeneous shape crash from earlier this session — a path-key mismatch between the InsightFace detector and the embedding cache writer left every FaceRecord.embedding_normalized = None. The defensive filter I'd added to the quality-gate step then dropped all 186 faces, leaving core_indices = []. The next step's input validator caught the empty list and aborted with the message you saw. Root cause is already fixed (canonical-path normalization landed earlier this session); the error reproduces only against a Python process started before that fix.

1 · The chain (8 steps) and where it broke

All 8 unified clustering steps shown. The bug lives in step 2; its consequence cascades through 5 and surfaces as an apparently-clean error at step 7. None of the intermediate steps logged anything alarming — that's the diagnosability gap the logging alignment closes.

2 · Why this looked different from the inhomogeneous shape crash

Both crashes have the same root cause but surface at different steps depending on what other fixes are present:

Defensive filter in quality_gate?What happensError site
No (your earliest run) Faces with None embeddings pass through quality gate; kNN tries np.array([None, ndarray, None, ...]) build_face_knn_graph: ValueError: inhomogeneous shape (186,)

So the two crashes were the same bug, caught at two different points by two different safety mechanisms. The newer "empty core_indices" error is strictly preferable to the numpy crash — it identifies which step is unhappy and which context key is missing. But neither error told you why the embeddings hadn't attached. That's where logging comes in.

4 · The fix already in place

sim_bench/pipeline/steps/insightface_detect_faces.py around line 181, landed earlier this session:

# spec-040 A1 bugfix: the embedding dual-write in extract_face_embeddings
# keys records by canonical forward-slash paths (see _generate_cache_key).
# Store the same canonical form here so the lookup succeeds on Windows.
canonical_path = str(image_path).replace("\\", "/")
records.append(FaceRecord(
    ...
    image_path=canonical_path,
    ...
))

Verified by the 2026-05-23 real-album run (122 images, 340 faces, 33 clusters, zero alignment/cluster errors past this point).

5 · Lessons for the architecture

Issue surfacedMechanism that catches it next time
A producer and a consumer disagree on a path-key encoding Defensive filter in quality_gate_faces already logs WARNING with a pointer to "producer dual-write regression?"
The warning is lost when the terminal closes Logging alignment — every surface now persists to logs/<ts>/<surface>.log
Step validator's error message names a context key but not the upstream step that should have populated it Open follow-up: the executor's validator could include "produced by step X" in its error. Tracked as a small enhancement to sim_bench/pipeline/executor.py.
"Empty" vs "missing" context keys are different conditions but produce similar errors Pandera-style schema on PipelineContext (out of scope for now) — would express "core_indices: non-empty list of int" as a typed constraint instead of an ad-hoc validator string.
