Logging — Where Albumify Writes, Why v2 Is Silent, and How to Align

2026-05-24 · spec-041 follow-up · same "one standard" principle, applied to logs

1 · What's already in the repo

Albumify (the FastAPI app) does have proper file logging — set up in sim_bench/api/logging.py:

def setup_logging(base_dir="logs", level=INFO, console=True) -> Path:
    timestamp = datetime.now().strftime("%Y-%m-%d_%H-%M-%S")
    log_dir = Path(base_dir) / timestamp                # logs/2026-05-24_10-30-00/
    log_dir.mkdir(parents=True, exist_ok=True)
    log_file = log_dir / "api.log"

    logging.basicConfig(
        level=level,
        format='%(asctime)s - %(name)s - %(levelname)s - %(message)s',
        handlers=[
            logging.FileHandler(log_file, encoding='utf-8'),    # → file
            logging.StreamHandler(),                            # → console
        ],
        force=True,
    )
    return log_dir

This is called once at FastAPI startup. Critically it configures the root logger, so every logging.getLogger(__name__) in the process — in face_cluster/*, sim_bench/pipeline/*, anywhere — automatically inherits both handlers. No per-module wiring needed.

That's why your logs/ folder is full of 2026-01-30_10-41-26/-style subdirs each containing api.log. Every FastAPI process leaves a tracked subdir behind.

2 · Why v2 is silent

v2 never calls setup_logging. Look at app/face_clustering_v2/main.py:

import streamlit as st
from app.face_clustering_v2.tabs.run_tab import render_run_tab
# ... no logging setup, ever ...
st.set_page_config(...)
st.title("Face Clustering — v2 (spec-040)")
render_run_tab()

When the v2 process starts, the root logger has whatever default config Python ships with (a StreamHandler writing to stderr at WARNING level). Every logger.info(...) below WARNING is silently dropped; every logger.warning(...) goes to stderr — which Streamlit captures and prints to the terminal that launched it. Nothing reaches disk.

3 · Current state (asymmetric)

Today: same module code, two different fates depending on which app started the process. Albumify's setup_logging configures the root logger; v2 doesn't, so its logs evaporate.

4 · The proposed alignment

One shared module, every surface calls it on startup.

Step 1: extract the API-specific logger into a shared module

Rename sim_bench/api/logging.py → sim_bench/logging_setup.py (or similar). It's not API-specific; the only reason it lives under api/ is historical.

# sim_bench/logging_setup.py
def setup_logging(surface: str, *, base_dir="logs", level=INFO, console=True) -> Path:
    """
    Configure the root logger to write to logs/<timestamp>/<surface>.log.

    surface: "api" | "fc_app_v2" | "fc_app_legacy" | "cli_run_v2" | ...
    """
    timestamp = datetime.now().strftime("%Y-%m-%d_%H-%M-%S")
    log_dir = Path(base_dir) / timestamp
    log_dir.mkdir(parents=True, exist_ok=True)
    log_file = log_dir / f"{surface}.log"

    handlers = [logging.FileHandler(log_file, encoding='utf-8')]
    if console:
        handlers.append(logging.StreamHandler())

    logging.basicConfig(
        level=level,
        format='%(asctime)s - %(name)s - %(levelname)s - %(message)s',
        handlers=handlers,
        force=True,
    )
    return log_dir

Step 3: aligned diagram

After alignment: every entry point calls the same setup_logging with its surface name. Same format, same dir layout, same handlers. Module-level getLogger(__name__) calls inherit automatically — no per-module wiring needed.

6 · The principle

This is the same principle as FCParams → UI_SPEC: one document defines the standard; every surface reads from it. The FCParams refactor put the parameter contract in one place. This puts the logging contract in one place. Both follow the rule you stated: "one specification that everyone reads from, true for any parameter in any GUI" — extended naturally to "true for any side-effect any surface emits."

What an arch test would enforce

def test_every_entry_point_calls_setup_logging():
    """Lock in the alignment — adding a new app/script without calling
    setup_logging is a check-list failure at PR time."""
    ENTRY_POINTS = {
        "sim_bench/api/main.py":              "api",
        "app/face_clustering_v2/main.py":     "fc_app_v2",
        "app/face_clustering/main.py":        "fc_app_legacy",
        "scripts/run_v2.py":                  "cli_run_v2",
    }
    for path, surface in ENTRY_POINTS.items():
        src = Path(path).read_text(encoding="utf-8")
        assert "setup_logging(" in src, f"{path} does not call setup_logging"
        assert f'"{surface}"' in src or f"'{surface}'" in src, (
            f"{path} calls setup_logging but not with surface={surface!r}"
        )
